## 先使用，需要时再保存到云端

打开地图即可选择地区。详情中的到访选项按已保存状态显示：已去过的地区勾选，尚未到访或已取消的地区不勾选。勾选后保存可添加首次到访日期和旅行笔记；取消勾选后保存会移除这段足迹，再次打开或刷新后保持未去过。游客草稿保存在当前网站、当前浏览器或 App 的本地存储中，正常刷新或重新打开可以恢复。

本机草稿不会自动出现在其他设备。清理浏览器数据、卸载 App 或更换设备前，请保存到云端或导出 CSV。CSV 目前用于另存备份，尚不支持导入。

点击“保存到云端”默认打开邮箱登录页，新用户可切换到“注册”，无需 GitHub 账号。注册需输入两次一致的密码，并完成邮箱验证。保存请求绑定发起请求时填写的邮箱；登录后先读取该账号已有的云端存档，再处理待转存草稿。

同一地区存在不同日期或笔记时，已有云端记录保持不变，完整的临时草稿会保留供整理；其他可合并的足迹可以正常转存。只有服务器确认且本机草稿未继续变化时，才会清理已成功转存的草稿。保存失败时保留输入并提供重试；多个页面同时修改会提示版本冲突，避免覆盖先前修改。

云端存档按账号隔离。同一邮箱登录后可以继续读取自己的存档，本机草稿不会自动写入其他账号。网页只包含公开的 Supabase 项目地址和 publishable key，不包含数据库密码、服务端私密密钥或邮件密码。

## 一家人的旅行足迹

家长用一个邮箱登录后，可在顶部“管理成员”添加家庭成员。每个账号最多 4 人（包括默认的“我”），孩子只需昵称，不需要邮箱。每人使用不同的旗子颜色；地区、城市、名胜、到访日期、笔记和护照分别记录。

“当前记录人”决定详情保存给谁，也决定清单与统计显示谁的记录。“地图显示成员”支持多选：共同到访的地点并排显示多面旗，点击某人的旗子会切换到他的详情。取消勾选成员只隐藏地图标记；取消某人的到访只移除他的那条足迹。

原有地区和名胜存档保持在原表中、归在“我”名下。成员信息及孩子的记录使用独立的 `shanhe_family_archives`，通过账号隔离与版本检查保存。当前不提供删除整位成员；编辑昵称或颜色不会改变记录归属。游客仍可先为自己记录，添加家人需要登录。

数据库部署前先执行 `supabase/migrations/20261028100923_shanhe_family_archives.sql`，再更新网页。

## 旧足迹如何保留

海外旧省州足迹按已核实的首府城市归档，原日期、笔记和更新时间完整保留。云端在事务中先备份当前存档再迁移，不覆盖用户迁移前的最新整理。目标城市已有足迹、多条旧分区对应同一城市或首府不能唯一核实时，旧记录单独保留，可在“我的足迹”中整理；不会自动合并或丢弃。云端首府迁移只执行一次，当前城市存档读取时不重复迁移。

大陆（含海南）在 2.4.0 恢复地市级，旧县区按已核实的所属地市一次归档。目标城市已有记录时保持原样；没有城市记录时，选有日期且最早的一条县区记录，日期相同或均为空时按旧 ID 稳定排序。其他县区记录完整保留在城市详情、足迹清单和 CSV 中，不再计入城市数量或插旗。城市取消到访后，历史县区记录不会再次生成该城市的旗子。

数据库迁移会在同一事务中保存完整原始存档及迁移说明，再更新记录键和版本。重复执行同一迁移不会再次搬移数据。台湾和港澳回迁沿用完整备份、保留字段与幂等规则；发布步骤和备份规则见[世界与县区存档升级说明](supabase/WORLD-MIGRATION.md)。

新版游客草稿使用独立的 v5 存储，优先读取 v5，再读取旧 v4、v3、v2、v1；首次成功保存才写入 v5，旧版本原始数据保留。县区归市和更早的海外首府转换只在旧草稿首次升级时执行；当前 v5 存档不重复转换。待转存草稿同步升级并保留旧备份；账号不一致、版本冲突或本机保存失败时不覆盖云端。更早的本机足迹可在登录后的“我的存档”中主动导入，原本机备份不会被清除。导入只能读取当前域名、当前浏览器或 App 内的数据，原 Sites 网址与 GitHub Pages 的本机记录不会自动互通。

## 部署与验证

网页由 GitHub Pages 提供静态托管，账号、邮箱验证及个人存档由 Supabase 提供，无需自购云主机。部署者需按 [Supabase 配置说明](supabase/README.md)配置数据库、邮件与认证返回地址，并按[本轮升级顺序](supabase/WORLD-MIGRATION.md)协调数据库、新网页与 Android 版本发布。

仓库根目录需直接包含 `index.html`、`.nojekyll`、前端脚本和 `assets/`。将生产文件发布到 Pages 使用的分支与根目录，测试、模拟登录工具、预览服务器、密钥及原始缓存不属于网页发行包。`cloud-config.js` 仅可包含公开项目地址和 publishable key。

本地验证覆盖地图 ID 与几何一致性、搜索和统计、游客草稿升级、同地区冲突保留、账号隔离、版本冲突、旧客户端拒写及迁移幂等。迁移 SQL 使用隔离 PostgreSQL 环境执行测试，不用真实用户旅行记录进行增删测试。浏览器模拟云端已验证市级地图、历史县区内容保留、本人和孩子取消到访后刷新不再插旗；发布时检查公开网页、APK 和实际云端连接。

## 数据来源、许可与快照限制

地图使用分级边界快照并做过显示简化。各来源的时间、行政层级与边界口径不同，单位数量不能作为现行法定行政区划统计；极小岛屿、飞地和后续区划调整可能未完整反映。地图用于旅行足迹展示，不作为测量、导航或法定边界依据，也不表示对争议地区归属的判断。

- 中国大陆及港澳使用[阿里云 DataV GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector)。原始边界版权归原权利人所有，没有将其重新声明为开源许可或公共领域数据。
- 台湾县市资料来自[內政部國土測繪中心](https://data.gov.tw/dataset/7442)，依据[政府資料開放授權條款－第 1 版](https://data.gov.tw/license)，使用 [plotdb/pdmaptw v2.4.0](https://github.com/plotdb/pdmaptw/tree/v2.4.0) 的 2025-03-18 简化边界并进一步加工。
- 世界及大部分州省边界来自 [Natural Earth](https://www.naturalearthdata.com/)，其地图数据为 [public domain](https://www.naturalearthdata.com/about/terms-of-use/)。Made with Natural Earth.
- 海外城市点主要来自 Natural Earth 的 Populated Places，缺口由 [GeoNames](https://www.geonames.org/)补充；具体固定版本、许可、行政归属例外和首府依据见[海外城市说明](assets/geo/world-cities-sources.md)。
- 印度尼西亚 38 省使用 [denyherianto 的地图数据](https://github.com/denyherianto/indonesia-geojson-topojson-maps-with-38-provinces)，按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)提供。
- 柬埔寨、老挝及缅甸的补充边界包含 © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright) 数据，部分经 [geoBoundaries](https://www.geoboundaries.org/)发布。相关地图数据库衍生文件与汇总索引按 [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/)提供；私人旅行记录不属于分发的地图数据库。

固定来源、处理方法、文件级许可和署名详见[中国数据说明](assets/geo/china-data-sources.md)与[世界数据说明](assets/geo/world-data-sources.md)。地图 GeoJSON 可在 `assets/geo/` 获取。D3 与 Supabase SDK 的许可分别见 [D3-LICENSE.txt](assets/D3-LICENSE.txt) 和 [SUPABASE-LICENSE.txt](assets/SUPABASE-LICENSE.txt)。
